# zhangkai.me

张凯的个人主页与技术笔记。静态 HTML 部署到 GitHub Pages，没有前端框架。

## 本地开发

需要 Node.js 20 或更新版本，以及用于本地预览的 Python 3。

```bash
npm ci
npm test
npm run build
python3 -m http.server 8000
```

构建会更新文章 HTML、首页精选列表、归档列表及其结构化数据、sitemap.xml 和 robots.txt。预览服务只负责提供文件，修改 Markdown 后需要重新构建。

## 编辑内容

- `posts/*.md` 是全部文章的来源；对应的 `posts/*.html` 是提交到仓库的生成页，不要直接修改。
- `index.html` 维护首页介绍与页面结构，`blog.html` 维护归档页结构。带有 `posts:*:start/end` 注释的区域由构建器生成，保留标记。
- `assets/site.css` 是全站样式，`assets/theme.js` 处理三种主题模式。文章与首页共用，不再复制到各页面。
- `scripts/build.js` 生成静态输出，`tests/` 包含构建与主题的回归测试。

新增文章时使用下面的单行元数据格式，正文保留一个与 `title` 相同的一级标题：

```markdown
---
title: 文章标题
date: 2026-10-23
category: Java 后端
description: 简洁说明文章讨论的具体问题。
---

# 文章标题

正文。
```

`date` 是首次发表日期。实质修订时增加或更新 `updated: YYYY-MM-DD`，不要用构建日期刷新旧文章。可选的 `featured: 1` 是首页精选顺序，序号须为正整数且不重复；首页最多展示前三篇，归档按首次发表时间倒序排列。没有设置精选的文章仍会出现在归档中。

构建器验证日期、必填字段、精选序号和一级标题。代码块按原文转义显示；Markdown 中主动书写的 HTML 仍按作者提供的内容输出，因此不应把未经审查的外部输入直接作为文章源文件。

删除文章时，同时删除对应 Markdown 和生成的 HTML，再构建以更新入口与 sitemap。首页与归档不声明未经确认的更新时间；文章的 sitemap 日期与结构化数据来自 `updated`，未填写时使用 `date`。

## 验证与发布

`npm test` 使用 Node 内置测试器，检查代码块转义、元数据同步、日期校验、构建可重复性，以及存储不可用时的主题切换等行为，不需要安装浏览器依赖。

修改页面布局后，还应在浏览器中检查窄屏与桌面、浅色与暗色主题、键盘焦点、文章链接和横向溢出。测试并不验证博文讨论的支付或数据系统实现。

仓库现有 CI 会在相关变更推送后运行测试与构建，并提交生成文件。实际发布仍由 GitHub Pages 设置决定。不要为本地预览执行推送或发布。
